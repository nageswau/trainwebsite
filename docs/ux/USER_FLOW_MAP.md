# User Flow Map

Generated by `prompts/07_UX_SCREEN_AND_FLOW_CATALOG.md`. Traces the confirmed business processes
(`docs/product/BRD.md` §7) through the actual screens in `SCREEN_CATALOG.md`. Screens drive from
features, which drive from PRD/BRD — nothing here introduces a step not already backed by an
approved Feature ID.

## Flow 1 — Domestic admissions handoff → enrolment → payment → learning

```
SCR-PUB-014 (Course detail)
  -> SCR-PUB-012 (Enquiry form) --[Zoho CRM webhook]--> SCR-ADM-004 (Enquiry list, IT Admin)
  -> SCR-ADM-006 (Enrolment review/approval, IT Admin)
  -> SCR-STU-001 (Trainer/slot selection, capacity 20, locked once booked)
  -> SCR-STU-010 (Digital agreement — blocking step)
  -> SCR-STU-012 (Payment checkout, Razorpay)
  -> SCR-STU-002 (Student dashboard, now active)
  -> SCR-STU-003 (Live class join) + SCR-STU-005 (Assignments) [ongoing]
  -> SCR-TRN-010 (Attendance marking) + SCR-TRN-009 (Grading) [Trainer side, per session]
  -> SCR-STU-009 (Certificate download) [on completion]
```

## Flow 2 — Overseas application: enquiry through visa

```
SCR-OVS-001/002/003 (Country/University/Course discovery)
  -> SCR-OVS-004 (Application/interest submission — same Student identity, DEC-ROLE-001)
  -> SCR-OVS-005 (Counselor: eligibility evaluation)
  -> SCR-OVS-006 (Student: status tracker) <-> SCR-CNS-002 (Counselor: assigned-student case view)
  -> SCR-OVS-007 (Document upload against checklist)
  -> SCR-VISA-001 (Visa checklist) -> SCR-VISA-002 (Interview prep) -> SCR-VISA-003 (Status tracking)
  -> [Enrolment — terminal state not yet named in the base codebase; see FEATURE_QUESTIONS.md item 4]
```

Exception paths (rejection/waitlist/deferral) are **not drawn** — they don't exist in any approved
feature yet (`PRD_OPEN_ITEMS.md` item 5). Do not infer a branch here that isn't backed by a screen.

## Flow 3 — Agent referral → commission

```

  -> SCR-OVS-004 (student applies, linked to this agent)
  -> SCR-AGT-003 (Agent: referred-student roster/status, read-only tracking)
```

## Flow 4 — University Representative review (base role)

```

  -> SCR-UNI-002 (Rep reviews, posts admission update, uploads offer letter)
```

## Flow 5 — Employer hiring (net-new role, coexistence with Placement Team undefined)

```
SCR-EMP-001 (Employer registration) -> SCR-EMP-002 (Employer dashboard)
  -> SCR-EMP-003 (Job posting)
  -> SCR-EMP-004 (Candidate search, GDPR-scoped) -> SCR-EMP-005 (Candidate profile)
  -> SCR-EMP-006 (Shortlist) -> SCR-EMP-007 (Interview scheduling) -> SCR-EMP-008 (Interview list)
```

**This flow's relationship to the base codebase's existing Placement Team flow
(`SCR-ADM-008`/`009`/`010`) is explicitly undefined** — `FEATURE_QUESTIONS.md` item 1. Both flows
are catalogued as parallel, independent paths; do not assume they merge (e.g. "Employer posting
requires Placement Team validation") without confirmation — that would be inventing a business
rule neither BRD/PRD nor the base codebase states.

## Flow 7 — School Portal: onboarding → Coordinator roster → Principal/Teacher/Parent visibility
(net-new, added 2026-09-14, `DEC-SCOPE-011`/`DEC-SCOPE-010` part 1, onboarding extended same day
per `DEC-SCOPE-012`)

```
SCR-SCH-010 (Overseas Admin: partner schools list + create-school form on the same screen --
     SCR-SCH-011's separate /new route merged in during SCH-003's build, 2026-09-14 -- creating
     seeds the Coordinator account too, active immediately, no approval gate, SCH-003-AC04)
  -> SCR-SCH-012 (Coordinator: team screen — invites Principal / Teacher / Parent)
  -> SCR-SCH-013 (each invitee accepts via their own token — single-use, institution-scoped,
       SCH-003-AC06) -> account active immediately, no approval gate

SCR-SCH-002 (Coordinator dashboard)
  -> SCR-SCH-004 (add one student by hand)
     -or- SCR-SCH-005 (bulk-upload roster: download template -> fill offline -> upload
          -> row-level accept/reject report, SCH-002-AC04)
  -> SCR-SCH-003 (student now appears on the roster)
  -> SCR-SCH-006 (Coordinator schedules an activity / marks attendance)

Once a student exists on the roster:
  -> SCR-SCH-001 (Principal sees it reflected in the school-wide dashboard, read-only)
  -> SCR-SCH-007 (Teacher sees it only if assigned to them, SCH-001-AC03)
     -> SCR-SCH-008 (Teacher opens that student's detail)
  -> SCR-SCH-009 (Parent sees it only if linked as their child, SCH-001-AC03)
```

## Flow 8 — School service-delivery: provisioning, results, career guidance, psychometric (net-new,
added 2026-09-14, `DEC-ROLE-006`; provisioning/portfolio/verify-publish steps added same day per
`DEC-SCOPE-013`/`014`/`DEC-ROLE-007` — supersedes the earlier "not drawn, module unconfirmed" note
this flow map carried under Flow 7)

```
SCR-SCH-021 (Overseas Admin or Super Admin: create Academic Team / Career Counselor / Psychometric
     Team account, assign their school portfolio -- one or more institutions, DEC-SCOPE-013/014)
  -> account active immediately, no approval gate, scoped to the assigned portfolio only

SCR-SCH-014 (Academic Team: portfolio-wide result status)
  -> SCR-SCH-015 (upload a result -- starts as Draft, visible only to Academic Team)
  -> SCR-SCH-016 (a DIFFERENT Academic Team member verifies -> publishes; same-actor restriction,
       DEC-ROLE-007 -- the uploader cannot verify/publish their own entry; each transition
       individually audited, SCH-006-AC04)
  -> Once Published:
       SCR-SCH-001 (Principal), SCR-SCH-002/003 (Coordinator, read-only), SCR-SCH-008 (Teacher),
       SCR-SCH-009 (Parent) all reflect it -- never before Published (SCH-006-AC02)

SCR-SCH-017 (Career Counselor: portfolio-wide student list)
  -> SCR-SCH-018 (add a guidance session / counselling note / recommendation -- visible to readers
       immediately, no gate confirmed for this content unlike results)
  -> Reflected read-only on SCR-SCH-001/002/003/008/009, same as above

SCR-SCH-019 (Psychometric Team: portfolio-wide student list)
  -> SCR-SCH-020 (assign an assessment / upload a report -- visible to readers immediately, no gate
       confirmed for this content)
  -> Reflected read-only on SCR-SCH-001/002/003/008/009, same as above
```

**Resolved, 2026-09-14** (previously "not drawn"): `academic_team`/`career_counselor`/
`psychometric_team` are scoped to a **school portfolio** assigned at account-creation time
(`DEC-SCOPE-013`), and their accounts are provisioned exclusively by **Overseas Admin or Super Admin**
via `SCR-SCH-021` (`DEC-SCOPE-014`) — a separate path from `SCH-003`'s four-school-side-role invite
flow, not an extension of it.
