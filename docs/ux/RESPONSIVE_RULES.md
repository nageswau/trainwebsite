# Responsive Rules

Generated by `prompts/07_UX_SCREEN_AND_FLOW_CATALOG.md`. Applies to all 96 screens in
`SCREEN_CATALOG.md`. Sourced from `NFR-RESP-001` (`CONFIRMED_CURRENT` — traces to the *original*
client requirement documents EVID-002/EVID-009, not just the superseded blueprint), so this is a
real requirement, not a proposal.

## Baseline rule (applies to every screen unless overridden below)

- **Mobile (< 768px):** single-column stack. Primary action always reachable without horizontal
  scroll. Secondary/tertiary content (filters, side panels) collapses behind a toggle or moves
  below primary content.
- **Tablet (768–1024px):** condensed navigation (icon+label or drawer), secondary panels collapse
  to tabs/accordions rather than side-by-side columns.
- **Desktop (> 1024px):** full multi-column layout as designed; no forced collapsing.
- No layout shift between loading and loaded state (skeleton placeholders reserve final-size space).

## Screen categories with distinctive responsive needs

| Category | Example screens | Note |
|---|---|---|
| List/browse screens with filters | `SCR-PUB-003/013`, `SCR-EMP-004`, `SCR-OVS-001/002/003` | Filter panel becomes a collapsible drawer on mobile/tablet, never permanently hidden |
| Multi-step/wizard forms | `SCR-STU-001` (slot booking), `SCR-EMP-007` (interview scheduling) | One step visible at a time on mobile; desktop may show step indicator + more context |
| Data-dense admin tables | `SCR-ADM-002`, `SCR-ADM-005`, `SCR-AGT-002` (approval queue) | Tables become stacked card lists on mobile — never a horizontally-scrolling table as the only mobile option |
| Dashboards with widgets | `SCR-STU-002`, `SCR-TRN-003`, `SCR-EMP-002` | Widgets reflow to a single column, ordered by priority (primary action/alert first) |
| Document/file upload | `SCR-STU-014`, `SCR-OVS-007`, `SCR-VISA-001` | Upload control remains a large, thumb-friendly tap target on mobile |
| Live-class join | `SCR-STU-003`, `SCR-TRN-003` join widget | Join button remains prominent at all breakpoints — this is a time-sensitive action |

## What is NOT specified here (open items, do not invent)

  Confirm before Contracts phase if precision matters.
- Native mobile app behavior — out of scope entirely; this project is a responsive web application
  only (EVID-002/009), no native app was ever confirmed.
