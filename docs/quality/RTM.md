# Requirement Traceability Matrix (rebuilt)

Generated by `prompts/10_TEST_CATALOG_AUDIT_AND_REBUILD.md`, NO-ASSUMPTION MODE. Supersedes the old
workbook's own `RTM` sheet (23 rows, organized by the old blueprint's `M01`–`M2x` modules) for
traceability purposes — that sheet is retained as historical input, not reused as current truth,
since its module boundaries and requirement IDs predate this project's confirmed scope changes.

Full chain per `CLAUDE.md`: **Evidence → Decision → BRD → PRD Requirement → Feature ID → Acceptance
Criteria → UX/Screen → Architecture/DB/API/RBAC/Integration → Test → Code → Release Evidence.**
This matrix covers the **Feature ID → AC → contract → test** segment; the Evidence→Decision→BRD→PRD
segment is already covered by `docs/features/FEATURE_TRACEABILITY.md`.

**Addendum, 2026-09-14** — a new "School" section added after this document's 2026-09-01 approval,
per `DEC-SCOPE-011`/`012` and `DEC-ROLE-006`. Original sections/content elsewhere are unchanged.

## How to read this matrix

Rather than one row per individual `-AC0#` (68 features × ~3 ACs each ≈ 200+ rows — too large to be
useful as a static document, and it would duplicate `FEATURE_ACCEPTANCE_CRITERIA.md`), this matrix is
one row per **Feature ID**, listing: contract documents it depends on, its old-catalogue test
coverage status, and its new/rewritten test coverage. Full test case detail is in `test_audit.json`
(old cases) and `TEST_REWRITE_PLAN.md` (new/rewritten cases).
