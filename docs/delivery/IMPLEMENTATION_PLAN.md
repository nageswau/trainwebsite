## 9. Rollback / checkpoint plan

- **Per-wave checkpoint:** each wave (0–3) ends with its own test-gate pass (§3, `RELEASE_BACKLOG.md`)
  before the next wave's features are considered startable in a shared environment — this is a
  quality gate, not a hard sequential block on parallel streams (`DEPENDENCY_PLAN.md`).
- **Migration rollback:** `OPS-002-AC02` already requires migrations to be transactional/rollback-
  safe — no schema change ships without a tested rollback path.
- **Deployment rollback:** `OPS-001-AC02` already requires a failed deployment to never leave
  production traffic pointed at a partially-updated instance — DigitalOcean App Platform's built-in
  rolling-deployment/rollback capability satisfies this, to be confirmed configured correctly during
  `OPS-001` build, not assumed.
- **Feature-flag/staged-rollout:** not designed here — no confirmed requirement calls for it; if
  needed for a specific high-risk feature (e.g. the commission two-gate), it's a build-time decision
  for that feature's own implementation, not a project-wide mechanism to invent now.

## 10. Release / UAT criteria

- **Per-milestone UAT:** M1 (MVP) requires a passing "Student Journey" and "Trainer Journey" UAT case
  (existing, `UAT-001`/`UAT-002`, retargeted per `RTM.md`); M2 requires a new "Overseas Student
  Journey" UAT case (`COVERAGE_GAPS.md` §4, not yet written — schedule its authoring alongside Wave 2
  build, not after); M3 requires "Employer Journey" (`UAT-004`, retargeted) and a new "Agent Journey."
- **Release gate (final, GATE-10):** per `CLAUDE.md`'s completion rule — a feature is complete only
  when its applicable acceptance, security, RBAC/resource-scope, test, build, migration, responsive,
  accessibility, and documentation gates all pass. This applies per-feature at merge time and
  cumulatively at each milestone.
- **No release ships against an NFR that is still `PROPOSED`/`OPEN` as if it were `CONFIRMED`** — per
  `COVERAGE_GAPS.md` §5, `NFR-PERF-001`/`NFR-SCALE-001`/`NFR-A11Y-001`/`NFR-REL-001` status must be
  resolved or explicitly accepted as unconfirmed in release notes, not silently treated as met.
