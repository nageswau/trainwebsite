# User Stories

Generated by `prompts/06_MASTER_FEATURE_CATALOG.md`. Written "where useful" per the prompt — for
the features carrying genuine, distinctive business rules, not mechanically for all 78. ID format
`US-<FEATURE-ID>-##`. Simple CRUD-shaped features (directory management, content browsing) are
adequately specified by their AC in `FEATURE_ACCEPTANCE_CRITERIA.md` alone.

## Enrolment and payment

- **US-STU-001-01:** As a Student, I want to see only trainer/time-slots that still have capacity,
  so I don't waste time selecting one that's already full.
- **US-STU-001-02:** As a Student, I want my slot locked once I book it, so I understand upfront
  that I can't casually change trainers mid-course.
- **US-STU-010-01:** As a Student, I want to see my EMI schedule and pending balance in one place,
  so I know exactly what I owe and when.
- **US-PAY-001-01:** As the platform, I need to verify a payment webhook's signature before marking
  a fee paid, so a forged/replayed webhook can never grant free access.

## Trainer delivery

- **US-TRN-006-01:** As a Trainer, I want to save an assessment as a draft before scheduling it, so
  students never see an unfinished question set.
- **US-TRN-007-01:** As a Trainer, I want to grade a submission and have the score/feedback appear
  immediately to that student, so there's no manual notification step I have to remember.
- **US-TRN-002-01:** As a Trainer, I want to see only the roster for my own batches, not the full
  student list, so my view stays relevant and I can't accidentally act on someone else's students.

## Domestic admin

- **US-ADM-003-01:** As an IT Admin, I want batch creation to reject a capacity above 20, so I can't
  accidentally over-enrol a slot the Student-facing UI already promised was capped.
- **US-ADM-005-01:** As an IT Admin, I want to approve or reject an enrolment after CRM sync, so a
  raw enquiry never becomes an active enrolment without a human check.

## Overseas application and visa

- **US-OVS-002-01:** As a Student, I want to submit Overseas interest using my existing account, so
  I don't have to create a second identity for a different part of the same platform.
- **US-OVS-003-01:** As a Counselor, I want to see only the students assigned to me, so my workload
  is manageable and I'm not responsible for cases I've never reviewed.
- **US-OVS-004-01:** As a Student, I want a notification whenever my application's stage changes, so
  I don't have to keep checking the portal manually — matching what I asked for directly in our
  planning conversation.
- **US-OVS-005-01:** As a Student, I want to see exactly which documents are required for my chosen
  country/university/course, so I don't upload the wrong things or miss something.
- **US-VISA-003-01:** As a Student, I want to see my visa case status update as it progresses, while
  understanding EduSphere is not the one deciding my visa outcome — matching the compliance language
  already present in the reference implementation's own visa-services copy.

## Agent and commission

- **US-AGT-001-01:** As an Agent, I want my account to stay inactive until Overseas Admin approves
  it, so the platform has a real gate before I can see or refer any student data.
- **US-AGT-002-01:** As an Agent, I want to see only the students I personally referred, so I can't
  see another agent's book of business.
- **US-AGT-003-01:** As an Agent, I want commission to appear automatically once my referred
  student's application is finalized and they've joined — not whenever an admin happens to enter
  it — so I can trust the timing reflects what actually happened.
- **US-AGT-004-01:** As an Overseas Admin, I want a separate approval step before a commission is
  marked paid, so claiming and paying are never the same action.

## Employer (net-new)

- **US-EMP-001-01:** As an Employer, I want to register my own company account, so I'm not
  dependent on EduSphere staff to represent my hiring needs on the platform.
- **US-EMP-003-01:** As an Employer, I want to search candidate profiles within whatever visibility
  limits EduSphere has approved, so I can find suitable candidates without seeing more of a
  student's personal data than I'm supposed to.

## Privacy

- **US-SEC-002-01:** As any user, I want to request export or deletion of my personal data through
  the platform itself, so I don't have to email support and hope someone follows up.

## Foundation

- **US-FND-002-01:** As the platform, I need every protected route to check role AND division
  server-side, so a Student token can never reach an Overseas Admin or IT Admin endpoint even if the
  frontend has a bug that would otherwise show the link.
