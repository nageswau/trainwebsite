## ADR-010 — Scaling methodology: concurrency/RPS-driven, not user-count-driven

**Status:** APPROVED (methodology only — this is a design principle applied per the prompt's
explicit instruction, not a Decision-Register item requiring separate user confirmation)
**Context:** `NFR-SCALE-001`'s 10,000-registered-user figure is `PROPOSED`/unconfirmed and, even if
confirmed, is the wrong metric for infrastructure sizing (see `SCALING.md`).
**Decision:** Stateless, horizontally-autoscaled web/API tiers; connection pooling and worker

**Consequence:** No specific instance-count or tier-size number is set anywhere in this
architecture — that requires a confirmed concurrency/RPS target that doesn't yet exist
(`SCALING.md`, final section).

## ADR-011 — Employer domain data model

**Status:** RESOLVED (Contracts phase, `docs/architecture/DATA_MODEL.md` §5.1, 2026-09-01)
**Context:** No Employer role/table exists in the base codebase; whether to extend existing
Company/Job/Interview tables with employer ownership or add a parallel table set was a real
data-modeling fork.
**Decision:** Extend the existing tables with a nullable `employer_user_id`/`owner_type` ownership
column rather than a parallel table set — chosen specifically because a parallel schema would
prematurely presuppose one answer to the still-open Employer↔Placement Team mediation question
(`FEATURE_QUESTIONS.md` #1). That workflow question itself remains open — this ADR resolves only
the schema shape, not the business process.

## ADR-012 — Overseas commission trigger-status mapping

**Status:** RESOLVED (Contracts phase, `docs/architecture/DATA_MODEL.md` §6.3, 2026-09-01)
**Context:** `FEATURE_QUESTIONS.md` item 4 — no "joined" terminal application status existed yet in
the base codebase's own status vocabulary.
**Decision:** `OverseasApplication.status` is fixed to an enumerated set derived directly from
`DEC-WF-001`'s confirmed stage sequence, ending in `enrolled`. The automatic commission trigger
(`AGT-003`) fires on a verified `ApplicationStatusHistory` transition to `enrolled` for an
application with an assigned agent. Exception-path statuses (rejected/waitlisted/deferred) are
deliberately **not** added — `DEC-WF-001` leaves those open, and inventing enum values for them
would exceed this ADR's technical-design mandate.
