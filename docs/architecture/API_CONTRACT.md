### 0.1 Pagination convention
Cursor-based (`?cursor=...&limit=...`, default `limit=25`, max `limit=100`) for collections that can
grow unbounded (enquiries, applications, students, jobs). Fixed small collections (a Trainer's own
batch list, an Agent's own referral roster — bounded by real-world scale, not by policy) are **not
paginated**, marked explicitly per endpoint.

### 0.2 Idempotency convention
Idempotency keys (`Idempotency-Key` header) are required only on financial/state-creating endpoints
where a client retry could double-create a record with real-world consequence (payment checkout
session creation, commission claim, GDPR request submission). Read endpoints and simple CRUD updates
do not require one — natural idempotency (PUT/PATCH semantics) suffices.

### 0.3 Standard error shape
`{ "error_code": string, "message": string, "field_errors": [{field, message}]? }`. 401 = not
authenticated. 403 = authenticated but not permitted (never a 404 that leaks resource existence to an
unauthorized actor, except where the resource-scope rule in `RBAC_MATRIX.md` explicitly says to mask
existence). 422 = validation failure, with `field_errors`. 409 = conflict (e.g. slot capacity race,
duplicate application).

| Method/Path | Auth | Scope | Notes |

A division mismatch (e.g. an `it` account posting `division=overseas`) is 403, not 401 — verified. |

| `POST /auth/logout` | Authenticated | Self | Invalidates refresh cookie server-side. |
| `POST /auth/forgot-password` | Public | — | Generic `{"accepted": true}` response regardless of whether the email exists (no enumeration) — verified by Playwright E2E. |
| `POST /auth/reset-password` | Public (token) | — | Token single-use and hashed at rest, consumed atomically (two simultaneous submissions yield exactly one success). Forgot-password links expire in 30 minutes; admin-provisioned **welcome** links (`DEC-SCOPE-019`, `ENH-003`) in 72 hours, and using one also sets `email_verified`. `new_password` is 10–128 characters (`422` otherwise, without consuming the link). Unknown, used, expired, revoked/superseded and inactive-account welcome links all return the same `400 "Reset token is invalid or expired"`. |
| `GET /auth/me` | Authenticated | Self | Returns identity + active `UserRoleAssignment` list (supports the multi-role-per-User model, `DATA_MODEL.md` §1.1). |
| `PATCH /auth/me` | Authenticated | Self | Profile field updates. **Addendum, 2026-09-20 (ENH-004 security review):** `profile.school_id` and `profile.university_id` (the two profile keys that scope access: the School portal, and a University Representative's applications) are server-owned. A request whose `profile.school_id` or `profile.university_id` differs from the caller's current value (including a user who has none) is **403** (`<key> cannot be changed here`), applies no other change from that request, and is audited as `profile.update_denied` (`outcome=denied`); echoing the unchanged value is accepted (the web "Update profile" form sends the whole profile). Only an admin route (`PATCH /admin/users/{id}`) sets them. `university_id` was added after the independent code review of ENH-004 (2026-09-20); other profile keys are unchanged (see `DEC-SCOPE-020`). |
| `POST /auth/change-password` | Authenticated | Self | `ENH-006` / `DEC-SCOPE-021`. Body `{current_password, new_password}`; `new_password` 10–128 characters and not only whitespace. `200 {"ok": true}`. `400 "Incorrect current password"` is the only message for a wrong current password. `422` for a malformed body, a length violation, a new password made only of whitespace (`"Password must not consist only of spaces"`), or a new password identical to the current one — none of these consumes an attempt. `429` + integer `Retry-After` (seconds) after 5 wrong current passwords in 15 minutes for that user, including for a correct password while blocked. `401` without a session (checked before body validation). Failures are audited as `auth.change_password_failed` (`outcome=denied`), a change as `auth.change_password`. A successful change also revokes the user's unused password-reset links. Other sessions are **not** invalidated (access tokens live 60 minutes, refresh tokens 14 days — accepted risk, `DEC-SCOPE-021`). **Not safe to retry blindly:** if a response is lost after the change was committed, a retry (which still carries the old current password) returns `400` and counts as a failed attempt. No `Idempotency-Key` (§0.2). Errors use FastAPI's `{"detail": …}` body, as every route does. |

**Auth type for every other route below:** Bearer access JWT unless marked **Public**. Every
protected route validates JWT signature, expiry, division, and role server-side before executing —
never a frontend-only gate (`FND-002`, `NFR-SEC-001`).
