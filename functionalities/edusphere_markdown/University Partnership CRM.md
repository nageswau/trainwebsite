**The key difference from a normal CRM**

I would design this so that **one university record becomes the central source of truth for the entire Edusphere organization**.

For example:

**University of XYZ**

→ Partnership status  
→ All contacts  
→ MoU  
→ Commission terms  
→ Courses  
→ Application requirements  
→ Meetings  
→ Visits  
→ Follow-ups  
→ Students interested  
→ Applications  
→ Offers  
→ Visa approvals  
→ Enrolments  
→ Commission received  
→ Partnership performance

So the **University Partnership Manager**, **Counsellor**, **Application Executive**, **Accountant**, **BDM and Management** all see the same university record, but each role sees only the information relevant to them. This is the structure I would recommend for your unified Edusphere CRM.
